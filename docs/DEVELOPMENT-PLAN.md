# 国行电视应用商店 — 开发计划

**版本：** V1.0

## 开发原则
采用标准 AI Vibe Coding 流程：先规划、再实现；先验证、再扩展；每次只做一个可检查的小任务。不允许一次性生成整个项目。

## 阶段 0：项目初始化
目标：建立规范、干净、可编译的工程。
- 创建项目目录。
- 保存 PRD、TDD、UI-DESIGN。
- 创建 AGENTS.md。
- 创建 README.md 和 CHANGELOG.md。
- 初始化 Git。
- 检查 Windows 开发环境。
- 创建 Android Studio 工程。
- 验证空工程能够编译。

验收：工程结构正确，文档齐全，Git 可用，Android 工程编译成功。

## 阶段 1：电视端 UI 原型
目标：在 TCL Q10L 上看到商店首页。
- 创建 Compose for TV 基础界面。
- 实现顶部横向导航。
- 实现精选应用区域。
- 实现横向应用列表。
- 实现遥控器焦点效果。
- 实现基本页面跳转。

首期使用本地假数据，只验证 UI，不接入服务器。
验收：能够通过遥控器完成首页基本操作，视觉符合 UI-DESIGN.md。

## 阶段 2：APK 安装验证
目标：验证电视端调用系统安装程序。
- 实现文件访问。
- 检查普通 APK。
- 调用 PackageInstaller。
- 获取安装结果。
- 处理取消、失败和签名冲突。

验收：在 TCL Q10L 上成功完成普通 APK 安装测试。

## 阶段 3：下载管理
目标：建立可靠下载模块。
- 创建下载任务。
- 显示进度和速度。
- 暂停和继续。
- 删除任务。
- 失败重试。
- SHA-256 校验。
- HTTP Range 断点续传。
- 重启恢复测试。

验收：电脑端自动化测试（MockWebServer 模拟 Range 续传、校验失败、重启恢复）全部通过；实机验证并入阶段 4 完成后的里程碑测试。

## 阶段 4：服务端 API
目标：建立应用数据服务。
- 初始化 FastAPI。
- 建立 PostgreSQL。
- 建立应用和版本数据模型。
- 实现分类和搜索。
- 实现应用详情。
- 实现下载信息接口。
- 建立反馈接口。

验收：API 自动化测试通过，并能够通过测试工具正常访问。

**里程碑测试 1（阶段 3+4 完成后）：** 电视端连接测试服务器，在 TCL Q10L 上验证真实下载、校验、续传和安装，由用户实机执行。

## 阶段 5：管理后台
目标：管理员能够独立管理应用。
- 初始化 React + Vite。
- 建立后台登录。
- 实现应用管理。
- 实现 APK 上传。
- 实现 APK 信息自动识别。
- 实现版本管理。
- 实现兼容性记录。
- 实现反馈管理。

验收：管理员能够完成应用从上传到发布的流程。

## 阶段 6：完整联调
目标：形成可实际使用的应用商店。
- 电视端连接正式 API。
- 展示真实应用数据。
- 下载真实安装包。
- 安装应用。
- 检查版本更新。
- 处理用户反馈。
- 进行兼容性和安全测试。

验收：核心用户流程在 TCL Q10L 上完整通过。

## AI 编程执行规范
每项任务必须：
1. 阅读相关项目文档。
2. 检查现有代码。
3. 给出简短实施计划。
4. 只修改必要文件。
5. 执行构建或测试。
6. 阶段完成并自测通过后提交 Git 并统一汇报。
7. 遇到需要用户决策、批准或实机测试的事项时停止等待；否则在已确认的阶段内连续推进。

## 版本管理
每完成一个可验证阶段，检查 Git 差异并提交。
建议提交节点：初始化工程、首页 UI 完成、遥控器导航完成、APK 安装完成、下载管理完成、API 完成、管理后台完成、完整联调完成。

## 测试节奏
日常开发以电脑端自动化测试为准，不要求每个阶段都在电视上测试。TCL Q10L 实机测试只在两个里程碑进行：阶段 3+4 完成后（里程碑测试 1）和阶段 6 完整联调。不通过 ADB 连接 TCL Q10L。
